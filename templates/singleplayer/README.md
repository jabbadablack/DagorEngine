# @GAME_NAME@

This is an independent daNetGame starter. No sample project or sample assets are
copied or required. Game rules are daScript ECS systems in `prog/scripts/game`;
UI and the embedded editor use Quirrel/daRg in `prog/scripts/ui` and the engine's
shared editor modules. Native application glue comes from the engine.

This game has its own `@GAME_NAME@.sln`, CMake workspace, presets and build script.
Open the solution in Visual Studio, or `CMakeLists.txt` in Rider/CLion. Run commands
from this project root; the engine's root command is not needed:

```sh
python prog/build.py                         # Code + shaders + assets + fonts + VROMFS
python prog/build.py code                    # Incremental native build
python prog/build.py shaders assets gui vromfs
python prog/build.py --no-build --run
python prog/build.py --level-editor
python prog/build.py --asset-viewer
```

`build.cmd`/`build.sh` wrap the local script. CMake can also be used directly:
`cmake --preset dev` then `cmake --build --preset dev`. Set `DAGOR_ENGINE_ROOT`
if your engine checkout moves; the project consumes its engine libraries and
build support in place. It does not invoke the engine's `dng.py` to build.

The ordinary debug/dev build includes the embedded editor (F2; the engine's
native F12 shortcut also works) and free camera (F10). No separate editor build
is needed. Use `editor.cmd`/`editor.sh` for the embedded editor,
`level-editor` for daEditor, `asset-viewer` for the asset viewer and `ui-editor`
for daRg UI preview. These launchers use the game-local build script. The engine tools must be
built once during engine bootstrap. The font is JetBrains Mono; its notice is included.

Editable sources live in `prog` and `develop`. `game` holds executable/content
build outputs and the development configuration. Shader descriptions are in
`prog/shaders` and use shared engine shader sources. `develop/assets/primitives`
contains original cube, sphere and plane DAG meshes generated by the project
creator. `develop/levels/starter` is the level workspace; the runtime ECS scene
is `prog/gameBase/gamedata/scenes/starter.blk`.

See `SCRIPTING.md` for the development structure. Content builds are explicit:
shaders, assets, fonts and VROMFS must be built before the first run.
